## Что это за симуляция (важно для правильных решений)

Существа эволюционируют **без функции приспособленности**. Никто не задаёт цель эволюции. Существо накопило энергию до порога → делится с мутацией. Кто успел поесть, тот и оставил гены. **Отбор возникает сам из экономики энергии.**

Это ALife, а **не** генетический алгоритм. Если ты когда-нибудь захочешь добавить `fitness()` — остановись, это архитектурная ошибка. Вся ценность продукта в том, что исходы непредсказуемы и за ними интересно наблюдать.

Полные обоснования решений — `PLAN.md`. Читай его перед архитектурными изменениями.

## ⛔ Инварианты. Нарушение = сломанный продукт

Это не стиль. Каждый пункт защищает работающую механику, и каждый **проверяется автоматически** (`node sim/check-invariants.ts`).

### 1. Ноль `Math.random()` в `core/src/`

Вся случайность — через сидированный `PRNG` (`src/prng.ts`).

На детерминизме («один сид → побайтно идентичная история») держатся **перемотка** и **догон мира при возврате в приложение**. Один `Math.random()` — и фоновая жизнь мира, ключевая фича продукта, разваливается. Проявится не сразу, а как «мир после resume не совпадает» — крайне дорого отлаживать.

### 2. Ноль импортов React / React Native / Skia в `core/src/`

Ядро headless. Так оно тестируется в Node за секунды, без устройства и симулятора. Это единственная причина, по которой экономику вообще удалось сбалансировать. Не тащи UI в ядро — рендер читает данные из ядра, не наоборот.

### 3. Состояние существ живёт в `useRef`, не в React-стейте

`setState` на каждом тике при 1000+ существах убьёт производительность. React обновляет только оверлей статистики, ~4 раза в секунду. Если увидишь `useState(creatures)` — это регресс, откати.

### 4. Тик отвязан от FPS (`SimClock` в `src/render.ts`)

Фиксированный timestep. Иначе эволюция идёт с разной скоростью на разных устройствах, и мир становится невоспроизводимым.

### 5. Всё, что влияет на будущее, обязано сериализоваться

**Реальный баг из истории проекта:** состояние блуждания в `RuleBrain` (`wanderX/wanderY`) не попадало в снимок. Восстановленный мир расходился с непрерывным. Тест поймал, глаз бы не поймал никогда.

Добавляешь поле, влияющее на симуляцию → добавь его в `serialize.ts` → прогони `sim/serialize-test.ts`.

## 🪤 Ловушки специально для LLM

Места, где правдоподобный код оказывается неправильным. Читай внимательно — это про тебя.

### ⚠️ `core/rn/` — НЕ ПРОВЕРЕННЫЙ КОД. Не доверяй ему как ядру.

`core/src/` прогнан тестами. `core/rn/` **написан по идиомам, но никогда не запускался** — у автора не было устройства и Skia.

Отсюда правило: **API Skia сверяй с установленной версией, а не с памятью.** Сигнатуры `Atlas`, `RSXform`, буфер-хуков менялись между версиями `@shopify/react-native-skia`. Твоё обучение почти наверняка содержит устаревший вариант, и он выглядит убедительно.

```bash
# Читай реальные типы, а не вспоминай:
cat node_modules/@shopify/react-native-skia/lib/typescript/src/index.d.ts
ls node_modules/@shopify/react-native-skia/lib/typescript/src/renderer/components/
```

Если `Atlas` не заводится — **запасной путь разрешён**: рисовать существ обычным `<Circle>` в цикле. Медленнее (много draw-call), но для первой сборки достаточно. Не изобретай сложное, пока простое не заработало.

### ⚠️ Не «чини» намеренные упрощения

Код выглядит неполным в нескольких местах **специально**. Это не забытые TODO:

| Выглядит как недоделка | На самом деле |
|---|---|
| `brainGenome` — пустая заглушка `{nodes: 0, connections: 0}` | Поле заранее заведено в геноме и сериализации, чтобы NEAT встал позже без миграции формата |
| Размножение только бесполое | Временное упрощение для чистой балансировки экономики. Половое — это Фаза 3+, у него своя ловушка (см. ниже) |
| Только травоядные, нет хищников | Хищники дают циклы Лотки–Вольтерры и роняют мир в вымирание. Отложены до Фазы 4 осознанно |
| `RuleBrain` — примитивные правила | Поведение зафиксировано намеренно: иначе не понять, что сломало энергобаланс |

Не реализуй их «заодно». Каждое — отдельная задача с высоким риском.

### ⚠️ Не вводи два вектора сложности сразу

NEAT, половое размножение, хищники — каждый может уронить мир в вымирание. Введёшь два за раз — не поймёшь, что виновато. Строго по одному, с headless-валидацией на графиках после каждого.

### ⚠️ Балансировку проверяй числами, а не глазами

Сломанную эволюцию визуально не отличить от рабочей: точки шевелятся в обоих случаях. Единственный надёжный метод — `node sim/run.ts` и графики. Именно поэтому Фаза 0 делалась headless.

### ⚠️ Две фундаментальные ловушки будущих фаз

Не баги — свойства реальности. Читай `PLAN.md` §4а и §4б, **прежде чем** браться:

- **NEAT без защиты новизны.** Каноничный NEAT спасает новые топологии видообразованием: свежая мутация сначала работает *хуже*, ей дают время. У нас отбор эмерджентный, механизма защиты нет — мутант с новым бесполезным узлом просто умирает. Открытая эволюция здесь будет **капризнее**, чем на демо классического NEAT. Это ожидание, а не дефект реализации.
- **«Двойная цена секса».** Бесполые плодятся быстрее (не тратятся на поиск партнёра) и в лоб **вытеснят половых за несколько поколений** — фича самоуничтожится. Это нерешённая загадка биологии, а не баг. Секс окупается только в **меняющейся среде** — и наши катаклизмы как раз такой двигатель.

## Ключевые абстракции

**`WorldGenesis`** — иммутабельные параметры творения (сид, размеры, стартовая популяция). Меняются только пересозданием мира.

**`WorldConfig`** — живые параметры среды, тик читает их каждый кадр. Главный рычаг — **`sunlight`**: приток энергии в мир. Понятная игроку абстракция вместо «скорости спавна еды».

**`TimelineEvent`** — единый механизм для правок игрока и катаклизмов: `{startTick, endTick, param, fromValue, toValue, easing}`. Огибающая, **не ступенька** — ледниковый период это плавный спад и подъём света. Событие в прошлом = правка «сейчас»; событие в будущем = запланированный катаклизм. Мир детерминирован от `сид + genesis + таймлайн`, поэтому перемотка воспроизводит и вмешательства игрока.
