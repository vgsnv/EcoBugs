# Эволюционный аквариум — план реализации

Наблюдательная ALife-симуляция с честной генетикой. Мобильное приложение, React Native + Skia.

---

## 1. Концепция и жанр

Продукт — **залипательная наблюдательная симуляция** искусственной жизни (ALife), а не игра с целями и не классический генетический алгоритм.

Ключевое различие зафиксировано: **эмерджентный отбор, без функции приспособленности**. Никакой заданной цели у эволюции нет. Существо, накопившее энергию до порога, размножается с мутацией — и всё. Кто выжил и поел, тот и оставил гены. Отбор возникает сам из экономики энергии. Именно это даёт непредсказуемые волны численности, дрейф признаков и вымирания — то, на что интересно смотреть.

Роль игрока — не управлять существами, а быть **режиссёром среды**: регулировать условия мира и планировать климатические события, наблюдая, как эволюция их переживает.

---

## 2. Ключевые решения (зафиксированы)

| Вопрос | Решение |
|---|---|
| Тип симуляции | ALife с эмерджентным отбором (не GA) |
| Хищники | НЕ в MVP. Добавляем в Фазе 4 (дают циклы Лотки–Вольтерры и риск вымирания — сложны в балансе) |
| Поведение существ в MVP | Простые правила (steering: к ближайшей еде, от края). Эволюционирующая мини-нейросеть — отдельная фаза после Фазы 2 |
| Стек | React Native + Skia (рендер), чистый TS для ядра |
| Фоновое развитие | Через детерминированный догон при resume (не реальный фоновый счёт) |
| Катаклизмы | Через журнал-таймлайн событий (см. §5) |
| Открытая эволюция (новые гены) | Уровень 2 через NEAT в фазе поведения. Геном расщеплён на `bodyGenes` (фикс. вектор) + `brainGenome` (растущая сеть). См. §4а |
| Размножение | Смешанный мир: половое и бесполое сосуществуют, способ — наследуемый ген. Фаза 0 намеренно только бесполая (временное упрощение). См. §4б |

**Почему поведение фиксируем в начале.** Пока балансируется энергетическая экономика, поведение должно быть неизменным. Если существа одновременно эволюционируют и «умнеют», невозможно понять, почему популяция стабилизировалась или вымерла — слишком много переменных. Сначала доказываем, что экономика сама держит устойчивый мир, потом добавляем обучаемое поведение как новый вектор отбора.

## 3. Архитектурные принципы (больно менять потом — заложить сразу)

1. **Ядро отдельно от рендера.** Симуляция — чистый TS-модуль без единого импорта из RN/Skia. Тестируется headless в Node/Jest.
2. **Состояние существ — в `ref`, не в React-стейте.** `setState` на каждом тике убьёт производительность. React отвечает только за меню и статистику.
3. **Фиксированный timestep**, отвязанный от FPS рендера. Иначе на разных устройствах эволюция пойдёт по-разному.
4. **Сидированный PRNG** (например `mulberry32`) вместо `Math.random`. Фундамент детерминизма: один сид → идентичная история. Нужен для перемотки, отладки и «поделиться миром по сиду».
5. **Пространственное разбиение** (grid) для поиска соседей — еды, партнёров. Без него запросы O(n²) и потолок в пару сотен существ.
6. **Рендер через Reanimated/Skia на UI-потоке** (worklets), чтобы игровой цикл не упирался в JS-бридж.
7. **Персистентность** состояния в MMKV: геномы (`bodyGenes` + `brainGenome`), позиции, энергия, сид, номер тика, конфиг, журнал событий. Сериализация с самого начала умеет оба поля генома, даже если `brainGenome` пока пуст.
8. **Поведение за интерфейсом `Brain`.** Движок дёргает `brain.decide(sensors)`, не зная, что внутри. Две реализации: `RuleBrain` (хардкод-правила, Фаза 0) и `NeatBrain` (позже). Позволяет внести NEAT без переписывания ядра.
9. **Детерминизм при NEAT.** Все мутационные выборы (какой узел/связь, возмущение веса) — из сидированного PRNG. Обход узлов/связей и обработка рождений — строго упорядоченными массивами (не полагаться на порядок ключей объектов). Innovation-счётчик глобальный и детерминированный при фиксированном порядке рождений. Так фундамент перемотки и догона не рушится.

## 4. Модель мира

### Геном — расщеплённый на две части

Геном делится на контролируемую и открытую части. Это разрешает конфликт «управляемая экономика ↔ открытая эволюция»: экономико-критичные оси остаются простыми и предсказуемыми, а открытость живёт в поведении.

**`bodyGenes` — фиксированный вектор `Float32Array`.** Критичны для экономики энергии, которую нужно держать управляемой и тестируемой.

- `size` — размер
- `speed` — скорость
- `metabolism` — базовый расход энергии
- `visionRadius` — радиус зрения
- `reproThreshold` — порог накопления энергии для размножения
- `mutationRate` — мета-ген: собственная скорость мутации
- `hue` — окраска (она же заметность/камуфляж)

**`brainGenome` — NEAT-сеть переменной топологии** (см. §4а). Открытая, растущая часть: именно здесь появляются новые гены. В Фазе 0 тривиальна/пуста, поведение даёт `RuleBrain`.

**Фенотип выводится из генотипа.** Важен trade-off: `metabolism ≈ f(size, speed)` — крупный и быстрый жжёт больше энергии. Без компромиссов эволюция скатится в один угол пространства признаков.

### Экономика энергии — сердце симуляции
- Еда спавнится с некоторой скоростью (задаёт ёмкость среды)
- Движение (∝ speed²) и метаболизм жгут энергию
- Накопил до `reproThreshold` → делится, отдавая ~половину энергии потомку с мутацией
- Отсюда автоматически берётся давление отбора и «окно жизни»

## 4а. Открытая эволюция: появление новых генов

**Проблема.** Фиксированный вектор `Float32Array` в принципе не умеет отращивать новые гены — смысл каждого гена живёт в нашем коде, мутация значений не может создать ось, которую мы не предусмотрели. Чтобы появлялись новые гены, геном должен кодировать **структуру, которую движок исполняет обобщённо**.

### Уровни открытости
- **Уровень 0** — фиксированный набор осей, эволюционируют только значения. Новых генов не бывает. (Так у нас с `bodyGenes`.)
- **Уровень 1** — пул спящих генов: заранее заложены признаки, стартующие «выключенными», мутация их активирует. Псевдо-открытость, но реально шипается. Опциональный дешёвый промежуток.
- **Уровень 2 — выбран.** Эволюционирует сама карта «геном → фенотип» через **NEAT**. Настоящие новые гены.
- **Уровень 3** — новые гены, меняющие правила игры. Фронтир ALife. Движок не может исполнить механику, которой в нём нет; «новизна» достигается новыми **комбинациями примитивов**, не новыми законами природы. За пределами плана.

### NEAT-геном (`brainGenome`)
Вместо вектора — два списка переменной длины:

```
Genome {
  nodes:       NodeGene[]   // { id, type: input | hidden | output }
  connections: ConnGene[]   // { inNode, outNode, weight, enabled, innovation }
}
```

Фенотип — нейросеть: входы = сенсоры (направление/дистанция до еды, своя энергия, локальный свет), выходы = действия (ускорение, поворот). Движок собирает и исполняет её каждый тик.

**Три мутации — здесь рождаются новые гены:**
1. *Изменить вес* — эволюция значений (как раньше).
2. *Добавить связь* — соединить два несвязанных узла.
3. *Добавить узел* — разбить связь A→B новым узлом (A→новый→B). **Это буквально появление гена, которого мы не задавали.**

Старт без скрытых узлов (входы→выходы напрямую), усложнение со временем — принцип complexifying.

**Упрощение под Фазу 0:** пока размножение только бесполое, кроссовера нет → машинерия выравнивания генов не нужна. Но с введением полового размножения (§4б) кроссовер и innovation-номера возвращаются — закладываем их поддержку в структуру NEAT-генома сразу, даже если в Фазе 0 не используем.

### Честная плата
Каноничный NEAT защищает новизну через **видообразование с fitness sharing**: новая топология сначала работает хуже, ей дают время. У нас **эмерджентный отбор без функции приспособленности** — механизма защиты новизны нет. Мутант со свежим, пока бесполезным узлом тратит на него ресурсы и умирает. Поэтому **открытая эволюция в чистом ALife идёт труднее и капризнее**, чем в NEAT с явным фитнесом. Это заложенное ожидание, не баг.

### Морфология (позже)
Чтобы новые гены меняли и внешность (требование визуальной читаемости — новое должно быть *видно*), есть **CPPN/HyperNEAT**: растущая сеть генерирует форму/окраску как функцию координат. Заметно сложнее, отложено. Начинаем с поведенческого NEAT.

## 4б. Размножение: смешанный мир (половое + бесполое)

**Цель — сосуществование обеих стратегий, а способ размножения сам является геном.** Не мы решаем, кто как размножается, — это наследуемый признак, эволюционирующий сам. Вопрос «половое или бесполое» превращается из дизайнерского выбора в объект наблюдения. Биологически честно: тля, дафнии, многие растения умеют оба способа.

- Ген `sexualTendency`: 0 = всегда деление, 1 = всегда партнёр, между — факультативно (зависит от условий).
- **Бесполое:** накопил `reproThreshold` → делится с мутацией. Как в Фазе 0.
- **Половое:** нужен поиск партнёра + кроссовер геномов родителей. Возвращает innovation-номера в NEAT-часть (см. §4а) — при скрещивании они снова нужны для выравнивания генов.

### Честная ловушка: «двойная цена секса»
Наивно смешать нельзя — фича самоуничтожится. У бесполых огромное преимущество скорости: **каждая** особь размножается сама, без затрат на поиск партнёра. В короткой перспективе они плодятся быстрее и **вытесняют половых за несколько поколений** — секс вымирает, остаётся скучное «победило деление». Это не наш баг, а **реальная нерешённая загадка биологии**: почему секс вообще существует, если бесполое выгоднее.

### Что удерживает секс живым — и стыкуется с нашим планом
Половое окупается, когда среда **меняется** и перемешивание генов помогает быстро подстраиваться:

- **Меняющаяся среда** — у нас уже есть катаклизмы и «солнце». Ледниковые периоды и качели света дают половым преимущество в моменты перемен, пока бесполые доминируют в стабильные эпохи. **Система катаклизмов становится двигателем эволюционной драмы:** игрок климатическими событиями дирижирует тем, какая стратегия побеждает.
- **Паразиты / гонка вооружений** (эффект Красной Королевы) — если позже введём хищников/болезни, ещё один мотор в пользу секса.
- **Храповик Мёллера** — бесполые клоны не могут вычистить вредные мутации рекомбинацией и со временем деградируют.

### Честный риск
Чтобы обе стратегии сосуществовали устойчиво, а не одна мгновенно съедала другую, нужен тонкий баланс условий выше. Это та самая капризность открытых систем: в части конфигов один режим будет доминировать. Это **нормально, если это наблюдаемый исход, а не баг** — смысл именно в том, чтобы смотреть, кто победит и когда.

Фаза 0 не затрагивается: только бесполое, чтобы изолированно мерить экономику. Смешанный режим входит вместе с половым размножением и NEAT.

## 5. Параметры мира: два класса + таймлайн

### WorldGenesis — параметры творения (иммутабельны)
Задаются один раз при создании мира, дальше неизменны. Меняются только пересозданием мира с нуля. В UI — отдельный экран «Новый мир», не панель настроек.

- длина генома
- размер grid / размеры мира
- стартовая популяция
- сид PRNG

### WorldConfig — параметры среды (живые)
Регулируются в любой момент. Живут в `ref`, тик читает актуальные значения каждый кадр.

- **солнечный свет** — главная абстракция: скорость притока энергии в мир (= скорость спавна еды). Понятный игроку рычаг: свет вверх → фотосинтез активнее, популяция растёт; вниз → голод, отбор жёстче
- питательность еды
- «температура» (влияет на метаболизм)
- вязкость среды (расход на движение)

### Промежуточный класс
`mutationRate`, `reproThreshold` на уровне мира — живые, но применяются **только к новым потомкам**, старые особи не трогаются.

### Журнал-таймлайн событий
Единый механизм и для реактивных правок, и для запланированных катаклизмов. Мир детерминирован от **«сид + WorldGenesis + журнал событий»**, а не только от начального конфига — поэтому перемотка воспроизводит и вмешательства игрока.

- Реактивная правка «сейчас» = событие с текущим тиком
- Запланированный катаклизм = событие с тиком в будущем
- Движок каждый тик проверяет, не наступило ли время события, и применяет его

**Катаклизм — огибающая, не ступенька:**

```
{ startTick, endTick, param, fromValue, toValue, easing }
```

Ледниковый период = свет плавно уходит вниз за N тиков, держится, плавно возвращается. Движок интерполирует каждый тик. Даёт нарратив: похолодание → ужесточение отбора → оттепель → демографический взрыв выживших.

## 6. Фоновое развитие и «кап»

Реального фонового счёта на мобилке нет (ОС усыпляет процесс). Решение — **детерминированный догон при resume**: движок берёт сохранённый тик и время, прогоняет пропущенные тики, применяя по пути все события таймлайна, попавшие в окно.

**Проблема стоимости.** Ушёл на час → секунды догона. Ушёл на неделю → миллионы тиков → зависание при открытии.

**Решение (MVP): кап + локальное уведомление.**
- Есть предел игрового времени, которое досчитывается в фоне. Дальше мир «замерзает» на месте остановки
- При уходе в фон планируется **локальное уведомление** на `now + капВремени`: «мир остановился, зайди обновить». Вернулся раньше — уведомление отменяется
- Кап становится честной механикой: у мира есть «завод», который надо периодически подкручивать. Приложение само зовёт игрока назад
- При возврате честно показываем: «пока тебя не было, прошло N поколений»

Огрубление счёта (крупный шаг в фоне, точность только при просмотре) — отдельная нетривиальная работа, отложена за пределы MVP.

## 7. Фазы разработки

### Фаза 0 — Headless-движок с тестами (без рендера)
Цель — доказать, что ядро «интересное», до вложений в графику. Балансировка притока энергии и метаболизма — самая сложная часть проекта, решается на графиках в тестах, а не глядя на рыбок. Только травоядные.

Заложить сразу: `WorldGenesis`, `WorldConfig` в ref, журнал-таймлайн, сидированный PRNG, grid, фиксированный timestep.

**Тесты определяют, что мир «интересный»:**
1. При разумном конфиге популяция не вымирает и не взрывается (стабилизируется в коридоре)
2. Средние значения генов *дрейфуют* со временем — значит отбор работает
3. Детерминизм: один сид → побайтно идентичная история
4. Sweep по солнечному свету: мало → вымирание, много → взрыв. Видно «окно жизни»

Результат смотрится как CSV/график в Node/Jest.

### Фаза 1 — Skia-рендер
Рендер стабильного движка. Простые точки/круги. Живой слайдер «солнце» — тот же инструмент балансировки, что использовался в тестах Фазы 0, отдаётся игроку.

### Фаза 2 — Видимая генетика
Размер / цвет / форма из генов. Оверлей статистики: поколение, средние значения генов, численность, график популяции.

### (после Фазы 2) — Эволюционирующее поведение (NEAT) + половое размножение
Замена `RuleBrain` на `NeatBrain` (см. §4а): растущая сеть в `brainGenome`, мутации «добавить узел / связь / вес». Здесь появляются новые гены. Новый вектор отбора. Отдельный крупный кусок. Внимание на плату за размер мозга и на капризность новизны без защиты видообразованием.

Сюда же вводится **смешанное размножение** (§4б): ген `sexualTendency`, поиск партнёра, кроссовер с innovation-номерами. Связать с системой катаклизмов как двигателем отбора между стратегиями. Следить за риском доминирования одной стратегии.

### Фаза 3 — Персистентность + догон
Сериализация в MMKV. Детерминированный догон при resume. Кап + локальные уведомления. Экран «пока тебя не было».

### Фаза 4 — Эмбиент, катаклизмы, полировка
- Экран «климатического планировщика»: таймлайн, куда игрок выкладывает будущие события
- Хищники (циклы «хищник–жертва»)
- Следы движения, частицы еды, цикл день/ночь
- Лёгкое взаимодействие (кинуть корм)
